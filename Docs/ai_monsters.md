# AIMonsters(仮): Azure の AI に敵を動かさせる MOD

## 決まったこと(2026-11-14)
### 共通
- ホストだけが入れる。API を呼ぶのもホストだけ
- モデル: Azure OpenAI の `gpt-6-luna`、思考量 `none`
  - 試験の結果: 3 体まとめて 1 回の呼び出しで 1.2〜1.7 秒、送信 566 トークン、返事約 75。
    `low` は 3.2〜4.1 秒で、判断はほぼ同じだったので使わない
- 動いている敵を全部まとめて、1 回の呼び出しで決めさせる。最短 2 秒に 1 回。返事が来るまでは次を送らない
- AI に決めさせるのは方針(狙う相手、追う・待ち伏せ・回り込み・引く・攻撃)だけ。実際の移動と攻撃はゲームの仕組みで行う
- 距離・見えているか・貴重品のそばに誰がいるかなどは MOD 側で計算して渡す(AI に座標の計算をさせない)
- API が失敗・遅延したら、敵は普段の動きに戻る
- API キーはホストの PC の環境変数(`AZURE_OPENAI_ENDPOINT` / `AZURE_OPENAI_API_KEY`)から読む。MOD・設定ファイルには入れない
- 送るのは数字と ID だけ。プレイヤー名は送らない(味方ローブの会話だけは発言の文を送る)

### 敵の AI(ローブ、クリーンアップクルー、ルーム)
- 始める: 敵の「見えた回数」(EnemyVision.VisionsTriggered)が、だれか 1 人について 1 以上になったら
- やめる: 誰も見えない状態が 10 秒続いたら、普段の動きに戻す
- 攻撃は普段どおりゲームが自動で行う。加えて、AI が `attack_player` / `attack_valuable` を選んだら、その相手を狙って攻撃させる
  (ルームの叩きつけで貴重品を壊す、など)
- MonsterTweaks と同じ敵なので、AI が動かしている間は MonsterTweaks の強化と競合しないようにする

### 味方の AI ローブ
- 出し方: 敵を倒したときのオーブ(大)(AssetManager.enemyValuableBig = ティア 3 の敵のオーブ)を、つかんで割ると召喚。レベル中に 1 回だけ
  - 出荷(抽出)で消えたときは数えない
  - 判定: 割れた(壊れて消えた)ときに、プレイヤーがつかんでいたか
- 敵のローブと見分けられるようにする(方法は調べて決める)
- すること: プレイヤーについて歩く、ほかの敵と戦う、チャットの指示で動く(「ついてきて」「○○についていって」「待って」「あの敵を倒して」「トラックに帰って/案内して」「敵を攻撃しないで」「戦って」など)
- プレイヤーは襲わない
- 会話: ローブの近く(15m)のチャットの発言を読んで答える。しゃべるのは**味方ローブから一番近いプレイヤー**のセミボットで、頭にゲーム内の英名「Robe:」をつける(2026-11-14 変更)
  - 読めるのは文字のチャットだけ(マイクの声は読めない)。発言は Azure に送られるので、一緒に遊ぶ人に伝える

### 追加で決まったこと(2026-11-14)
- MonsterTweaks との互換: 入っていても入っていなくても動く(参照はせず、入っているかはプラグイン一覧で調べる)。
  クリーンアップクルーの分身(上空で待機する本物の敵)は AI の対象にしない。AI が動かしている敵には目印をつけ、MonsterTweaks 側はその敵の強化を止める
- 敵の特性・強みの説明: 既定の英文を MOD に持ち、`BepInEx/config/AIMonsters/` のテキストファイルがあればそちらを使う(敵ごと・共通の説明)
- 味方ローブの会話: 近くの発言とローブの返事を直近 10 件ほど覚えて、毎回いっしょに送る(件数は設定)
  発言者は既定で番号(P1 など)。名前を送るかは設定

### 途中参加(LateJoinNow)との相性(2026-11-15 調査、AIMonsters 0.8.0 で対策)
ホストのログ(2026-11-14 のプレイ)で分かったこと:
- 途中参加は 8 回。味方のローブがいるレベルへの 4 回はすべて失敗。いないときの 4 回には失敗のしるしがない
  (3 回は動き出すまで確認。1 回は 22 秒で抜けたが、下の 10 秒後のエラーは出ていない)
  - 同じレベル(Arctic)で、召喚の前は成功、召喚のあとは 2 回とも失敗
- 失敗のとき: 参加者は読み込み画面のまま 30〜55 秒部屋にいて抜ける。ホストには、参加から 10 秒後に
  `PlayerCosmetics: No colors equipped after 10 seconds` が 2 行出る(参加者の PC で `LevelGenerator.Generated` にならないと、見た目が送られてこない)
- レベルの途中で生成した敵がいるだけでは失敗しない(MonsterTweaks のクリーンアップクルーの分身がいるレベルで成功している)
- 参加者側で何が止まるかは、参加者のログ(`Player.log` / `LogOutput.log`)がないと分からない。ゲームのコードを読んだ範囲では、
  ローブ・目印のオーブのどちらにも、読み込みを止める箇所は見つからなかった

対策(原因がどちらでも効くように、参加者の読み込みに一切関わらせない):
- 生成の記録を部屋から消す(`AllyLateJoin.Uncache`。Photon のイベント 202 を `RemoveFromRoomCache` で消す。`PhotonNetwork.Destroy` の中と同じ操作)
- 人が入ってきたら(`NetworkManager.OnPlayerEnteredRoom`)、味方のローブを `EnemyParent.Despawn()` で退場させ、目印のオーブを消す
- 読み込みが終わった合図 = その人から見た目の同期(`SetupColorsRPC` など)が届く、または動き始める。3 秒後に、その人にだけ生成を送り
  (イベント 202 を `TargetActors` で送る)、`SetupDone` を送り直してから、ついていく人の後ろに出直す
- ネットワーク越しに敵を消して作り直す方法は使わない(MOD なしの人の `EnemyDirector.enemiesSpawned` に消えた敵が残り、敵の番号がずれるため)

分かっている制限: 途中参加の人の PC では、味方のローブが敵の一覧(`EnemyDirector.enemiesSpawned`)の最後に入る。
味方のローブのあとに生成された敵(クリーンアップクルーの分身など)がいると、その人の PC だけ敵の番号がずれ、
「どの敵に倒されたか」の表示が違う敵になることがある(途中参加の人の一覧の順番は、もともと保証されていない)

まだ失敗するときに見るもの: 参加した人の `%USERPROFILE%\AppData\LocalLow\semiwork\Repo\Player.log`(MOD を入れているなら `BepInEx\LogOutput.log`)。
`level loading failed on this machine` や例外が出ていないか

## 調べること
- ローブ(EnemyRobe)・ルーム(EnemyShadow)・クリーンアップクルー(EnemyBombThrower)の状態の流れと、狙う相手・攻撃を外から指示する方法
- 各敵の攻撃が貴重品・ほかの敵にダメージを与えるか(当たり判定の設定はプレハブにあるので、ゲーム中に調べる)
- 味方ローブ: ほかの敵を狙わせる方法(ゲームの敵はプレイヤーしか狙わない)、プレイヤーへの攻撃を止める方法、プレイヤーの武器が当たったときの扱い
- オーブ(大)が割れたときの検出(つかまれていたか、出荷で消えたのではないか)
